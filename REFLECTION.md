# Reflection

Throughout these operating systems labs, the hardest concept for me was understanding synchronization and race conditions in multithreaded programs. It was challenging to understand how multiple threads could access the same shared variable at the same time and produce inconsistent results. Using mutex locks and condition variables helped clarify how synchronization works and why careful coordination is necessary in concurrent programming. One concept that clicked unexpectedly was how debugging tools like GDB and Valgrind can precisely identify logical errors, segmentation faults, and memory leaks. Seeing runtime behavior step-by-step made debugging much easier and improved my understanding of memory management in C. Among the project ideas introduced in the labs, I would most like to further develop the Unix-like shell project because it combines process creation, signal handling, pipes, redirection, and command execution into a practical real-world system programming application.
